# LOTWORKS — 非同期オークション仕様 v0.2

更新: 2026-10-31 / 出品アーカイブ・買い手競売・持ち込み消耗品を分けて扱う。

## A. 合意済みの不変条件
1. **出品時に商品は出品者のインベントリから消える。**
2. サーバーには出品時点の商品スナップショットが残る。
3. 一人の購入者が落札しても出品情報は直ちには消えず、**同じ出品データを他の購入者が別々に購入できる**。
4. **出品者の経済的な利益は一出品につき一回のみ。** 再購入・アーカイブ再利用による追加の売却益は発生しない。
5. 競売を利用する各プレイヤーのローカル経済は独立。全員で同じ需要・在庫数を共有する仕組みは不要。
6. 同時ログインを要求しない。会場はノミ市、素材、機械などの候補を持つ。
7. **購入者は拠点からアイテムを会場へ持参し、会場内で使用・消費する。** これは出品・購入とは別の行動である。

## B. 対人競売の未決定事項
- 入札が封印式、リアルタイム表示を模したゴースト式、即時解決式のどれか。
- 保存された入札方針/行動を競合として採用するか。行動が買い手の意思決定へどう影響するか。
- 一回の競売で複数ロットを回るか、終了・撤退のタイミングをどう定義するか。
- 出品者の一回分の利益を出品時、初回の売買確定時など、いつ確定するか。
- 同一購入者による同一出品の繰返し購入の可否。
- 掲載期間、再登場頻度、NPCとの混合、経済的な悪用対策。
- 購入品が「仮獲得」なのか即時所有なのか、戦利品のロスト条件と帰還時の扱い。
- 消耗品の対象、効果、入場時の持ち込み制限、使用成功・不発時の消費規則。

## C. ドメインモデル案（実装未着手）
- `ItemDefinition`: 商品/道具の種類と規則。
- `ItemInstance`: 個体ID、所有者、状態、構成、数量/使用回数。
- `LocalInventory`: 拠点所有物。
- `AuctionLoadout`: 競売へ持っていく所有品と資金の選択。
- `ItemUse`: 競売中の選択、対象、効果、**消費トランザクション**。
- `AuctionListingSnapshot`: 出品で消費した元アイテムの不変スナップショット。
- `AuctionEncounter`: 各購入者の独立した競売セッションと競合情報。
- `BuyerAcquisition`: 買い手世界に生成される独立した商品個体。
- `SellerSettlement`: 一出品に一回しか生じない売却益。

これらの名前・境界は開発用の案。DBやAPIの採用を意味しない。

### 例: 出品の再利用と、購入者の消耗品は別
1. Aが加工した機械Xを出品。Aの在庫から元商品が消え、`listing_X` が保存される。
2. Bが自分の世界から鑑定キットを持参し、Xの競売で使用する。**使った鑑定キットはBの資産から消費**される。
3. BがXを獲得できるかは、その場の競売ルールで決まる。鑑定キットを使ったことだけでは落札は保証されない。
4. Cが別の日時に `listing_X` と遭遇し、独立して購入することもできる。
5. Aが受け取る売却益は一回分だけ。B・Cの繰返しの購入が追加益を発生させない。

## D. 将来の整合性要件
- 元商品の出品消費とスナップショット登録は一つの原子的な操作として扱う。
- 一出品一回の支払いを `listing_id` に紐付けて重複排除する。
- 各買い手の取得商品個体は固有IDを持ち、他の買い手とは独立する。
- 持ち込みは「所有アイテムの使用可能範囲を移す」操作であり、**持ち込みだけで消費済みとしない**。
- 使用/消費処理のリトライで二重消費しない。消費成功時だけ、定義された効果を反映する。
- 落札決済の再試行で資金二重減算や商品二重付与をしない。
- 未決定の戦利品ロスト・撤退リスクを実装に勝手に組み込まない。

## E. PvPとして成立する条件
人の出品物や行動データがあるだけではPvPとはいえない。消耗品の使用対象・タイミングと、競合の意思決定が相互に影響するかを検証する。詳細な研究課題は `SESSION_DESIGN.md` を参照。
