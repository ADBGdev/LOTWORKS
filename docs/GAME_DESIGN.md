# LOTWORKS — ゲーム企画書 v0.2

更新: 2026-10-31 / 企画再設計中。確定と未確定を混同しない。

## 1. コンセプト
**小さなインベントリを舞台に、独立した工房を経営し、他プレイヤーの作った商品が出る非同期オークションで仕入れと駆け引きを行う。拠点で所有するアイテムを競売に持ち込み、使用・消費することで対人性と緊張感を生み出す。**

出発点は「Probably Stolen」型の査定・仕入れ・加工・保管・売却・再投資の快楽。広い移動空間や巨大な同期経済を作らず、狭いUIに意思決定を集約する。

### ねらう体験
- **拠点:** 所持品の蓄積、安全な整理、仕入れた商品の査定・限定的な加工・売却。
- **持ち込み:** 所有するアイテムのうち、会場で何を使うかを事前に選ぶ。
- **競売:** 商品を値踏みし、入札相手との駆け引きで、持参した消耗品を使うか温存するかを判断。
- **帰還:** 獲得品と残り資産を拠点の経営に戻す。その後に再び準備する。
- **損失:** 出費だけでなく、使用した自分のアイテムが消える。獲得済み戦利品の喪失方法は未定。

目指すのは、持ち込み前の判断、使う瞬間の判断、対人の駆け引きが互いに関係すること。単に競売画面に「消耗品」ボタンを増やすだけでは不足。

## 2. 主従とスコープ
当初の「工房・多産業経営中心」から、**オークションでの仕入れ勝負を先に検証する方向へ重点を移した**。ただし、工房を長期的にどの程度深くするかは未決定。

- オークションは資産を使って参加する勝負の舞台、工房は準備と持ち帰った成果の活用場所。
- 工房の栽培・生産・複雑な設備連鎖は、最初の面白さが確認できるまで保留。
- 外部のダンジョン探索など、追加の別ゲームを載せて複雑化しない。

## 3. 1サイクルの案（セッション方式は未確定）
1. 拠点で、競売に持っていく資金・アイテムを選ぶ。
2. 会場で他プレイヤー由来の商品や競合の行動に遭遇する。
3. 査定・入札・相手の行動への対応のため、持ち込み品を使用して消費する。**何に使えるかは未決定。**
4. 商品獲得・消耗品支出・資金変動を踏まえ、続行か終了を判断する。**撤退のルールは未決定。**
5. 拠点で獲得品を保有・簡易加工・売却・出品し、次の準備をする。

「連続ロットを巡って撤退する形式」は検討案であり、確定したゲーム規則ではない。

## 4. アイテムの二重の役割
- **経済資産:** 落札・保管・加工・出品の対象となる商品。
- **戦術的消耗品:** プレイヤーが所有し、競売へ持ち込み、使用したらインベントリからなくなる道具。

あるアイテムが商品と消耗品を兼ねるか、専用品を設けるかは未定。消耗品の効果候補: 鑑定、情報取得、競合への干渉、対抗措置。**すべて例示であり未採用**。

本質的な判断は「使えば勝ちやすくなるが、使った資産は戻らない」「今使うか次の機会へ残すか」「どの相手・どの品に使うか」。

## 5. 非同期の考え方
- 各プレイヤーは原則として独立した経済、在庫、設備、進行度を持つ。
- 他人の出品時の商品状態をサーバーに保存し、購入者ごとの独立した競売に使用できる。
- 出品者の商品は出品時に消え、売却益は1出品につき1回だけ。
- 他人の保存された入札方針を競合として利用する方法は**検討中**。その競合のプレイヤーに直接、実資産の損益が生じる仕組みは確定していない。
- 全員が同じ時間にログインする必要はない。
- 世界全体の需要・供給競争や、統一市場での価格形成をPvPの主題にしない。

## 6. 競売会場（方向性）
- ノミ市: 初期会場の候補。ジャンク・中古品・正体不明の品を目利きする。
- 素材オークション: 加工と素材評価に関わる発展候補。
- 機械オークション: 故障・部品・設備投資の発展候補。

増設は可能だが、最初はノミ市1会場で試作する。

## 7. 重要な設計課題
**消耗品の支出と資金損失だけでは、「すでに獲得した戦利品まで失うかもしれない」というエクストラクション特有の緊張とは同じではない。**

戦利品を持ち帰るまでの保護状態、他者の干渉、撤退リスクは未確定。無根拠な没収、賭け担保、持ち込み道具の自動没収を既定のルールにしない。

また、入札額が上がるだけのNPC挙動ではPvP感が薄い。相手の意思決定に対応してアイテムを使い分ける余地を検証する。

## 8. ソロ開発指針
- Godot 4.x、2D / Control UI、GDScript。
- まずは短い「持参 → 判断 → 使用・消費 → 取引結果 → 帰還」のループをプロトタイプ化する。
- コンテンツ量・世界観・フル生産経営の拡張より、対戦相手の判断に対して消耗品を使う面白さを優先する。
- 詳細は `SESSION_DESIGN.md`, `AUCTION_DESIGN.md`, `DECISIONS.md` を参照。
