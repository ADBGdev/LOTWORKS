# LOTWORKS — MVP / 検証計画 v0.1

## 目的
インベントリ経営と非同期競売が、一体の反復体験として面白いかを最小限のコストで検証する。技術的な規模や総コンテンツ量ではなく、1回の仕入れ・加工・再出品に再挑戦したくなるかを判断する。

## 初期実験の仮スコープ（数値は未確定の目安）
- Godot 4.x / GDScript / 2D Control UI。
- ノミ市1会場。素材・機械会場は後の拡張候補。
- 商品20〜30種類程度の仮データ。個体ごとの限定的な状態差を持たせる。
- 基本操作: 鑑定 → 入札/購入 → 保管 → 修理/分解/組み合わせ → 売却/再出品。
- 加工・修理による価値の違いを可視化する。
- NPC商品は供給不足対策として利用可能。
- 初期段階はローカルの出品スナップショットで動作検証し、以降に複数人でのデータ交換を検証。
- UIだけでループが成立するかを検証し、大きなワールドや3D物理は制作しない。

## 段階
### 0. リポジトリ準備（このコミット）
Godot project.godot、起動用シーン、ディレクトリ骨格、設計資料、agentルールを作る。**ゲームプレイは未実装**。

### 1. 単独経営の垂直スライス
在庫、商品個体、価格のあるアイテム、鑑定、ひとつの加工、保管/販売が一巡する。面白さを見てから種類を増やす。

### 2. 非同期競売のローカル試験
出品で元商品を消費しスナップショットを生成。2人分の独立した買い手世界へ商品を生成できること、売り手報酬が一回のみであることをテストする。競売ルールは最小構成から選定。

### 3. 実際のプレイヤー参加による実験
人間が準備した商品の鑑定・仕入れはNPCとの取引より面白いか。売り手の工夫が相手の判断に反映されるか。実際の他者データで検証する。

## 成否判定
- プレイヤーは自分から複数回の仕入れ・加工・再出品を試みるか。
- 鑑定・加工・設備差が、同じ商品への評価を変えるか。
- 売り手の工夫と買い手の判断が競売に意味を持つか。
- 楽しさが増えないインベントリ操作を自動化・縮小できるか。
- PvPがゲームの追加作業にならず通常の経営行動に埋め込まれているか。

## 非目標（初期）
- リアルタイムPvP / 全員が共有する経済 / マクロ市場の需要競争。
- 大規模3D、物理シミュレーション、NPC群の複雑な自律AI。
- 複数専門会場の同時完成、無制限のクラフト自由度。
- LLMによる価格・鑑定・競売の裁定。
